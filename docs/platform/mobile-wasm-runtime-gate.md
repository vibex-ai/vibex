# Mobile GPUI-WASM Runtime Gate

## Product Boundary

`apps/mobile-wasm` is the UI runtime bundled by `apps/mobile`. It is not a
WebUI, PWA, hosted application, or desktop-browser workbench. Its local Chromium
host exists only to exercise the WASM and host-bridge contracts without building
a native package.

The runtime must:

- identify itself as `capacitor_mobile_runtime`;
- identify browser execution as `development_and_test_only`;
- resolve only Compact or Medium shells, including at wide host viewports;
- emit no Service Worker, PWA manifest, or offline Web entry;
- use `WebRemoteBackend` while the PC `DesktopRuntime` remains authoritative.

## Current Status

- Development host: source-bound Chromium validation is available and carries
  no release or browser-support claim.
- Browser product: retired; Firefox, PWA, public hosting, Wide Web, and browser
  accessibility are not release targets.
- Android packaging: available through Capacitor. Every rebuilt APK returns to
  `not_tested` until physical results are captured for that exact artifact.
- Android physical validation: pending for the current package unless its
  source-bound evidence says otherwise.
- iOS physical validation: pending and requires a macOS/Xcode host.

The machine-readable sources of truth are:

- `docs/platform/evidence/mobile-wasm-host-gate.json`
- `docs/platform/evidence/wasm-android-build.json`
- `docs/platform/evidence/wasm-mobile-physical.json`

## Toolchain Contract

- GPUI and gpui-component revisions come from the root `Cargo.lock`.
- `wasm-bindgen-cli` must match the lockfile version.
- The WASM compiler is `nightly-2026-07-24`.
- The runtime uses `single_threaded_web`; no `SharedArrayBuffer` is required.
- `build.json` binds the source revision and WASM/glue/static hashes to the
  Capacitor-ready runtime.

## Development Host Coverage

The fixed local host validates real GPUI pixels, WebGPU failure diagnostics,
keyboard input, pointer/touch scrolling, appearance, lifecycle, bounded Fetch,
and WebSocket adapters at Medium and Compact viewports. It records no screenshot
and makes no claim about a deployable browser application.

Maximum shell: Medium. A 1280-pixel host must still select Medium; a 390-pixel
touch host must select Compact. Canvas existence alone is never a pass: the gate
requires nonblank pixel variance and a sized backing store.

Automated input validates adapter wiring only. It does not prove a physical CJK
IME, soft keyboard, clipboard menu, non-US hardware layout, mobile accessibility,
secure storage, camera, push, App Links, or background network recovery.

## Mobile Validation

The Android contract uses API 26 or later and target API 36. Packaging proves
construction only. Physical evidence binds each result to an exact APK hash and
records IME, touch, keyboard inset, Compact/Medium layout, Android Back,
rotation, lifecycle, network, secure storage, WebGPU pixels, clipboard, and
hardware-keyboard behavior independently.

Omitted scenarios remain `not_tested`; partial physical evidence never satisfies
the release gate. iOS results cannot be inferred from Android.

## Commands

```bash
pnpm capture:mobile-wasm-host   # writes metadata only; no screenshot
pnpm check:mobile-wasm-host
pnpm capture:wasm-android
pnpm check:wasm-mobile
pnpm check:wasm-gate
```

Evidence files are generated by their writer. Do not edit hashes or statuses by
hand, and do not promote development-host evidence to a product release claim.
