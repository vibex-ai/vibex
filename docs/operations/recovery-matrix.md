# Crash Recovery Matrix

This matrix distinguishes durable local-first state from runtime-only handles.
SQLite and explicit filesystem artifacts are
authoritative after restart. Frontend cache, live WebSocket state, PTY handles,
provider process handles, and Relay rooms are never authoritative recovery
inputs.

Durable `running` or `initializing` records are hints that a runtime check or
provider-owned resume attempt is required. They are not proof that work is
still active.

| Subsystem | Durable owner | Runtime owner | Restart behavior | Existing coverage | Gap/follow-up |
| --- | --- | --- | --- | --- | --- |
| Projects and workspaces | SQLite `projects`, `workspaces`, recent files, and workspace filesystem paths | Desktop/remote service workspace caches | Reopen from SQLite and validate current filesystem access before user actions. UI cache may prefill only after authoritative fetch. | DB migration smoke and workspace repository tests. | Release smoke should include workspace root moved/missing classification. |
| Agent sessions | SQLite `agent_sessions` plus provider bindings and timeline rows | `AgentManager`, provider adapter process/client handles, live event broadcaster | Session list and timeline reload from SQLite. Live channel is recreated. `running`/`initializing` sessions require provider-owned resume or explicit stale/error classification before being presented as active. | Provider-neutral session persistence/reload, timeline repository, catch-up tests. | Provider-specific real resume remains out of scope until adapters expose production resume support. |
| Provider bindings and resume metadata | SQLite provider binding rows and redacted native metadata allowed by adapter contracts | Provider adapter clients and native provider processes | Bindings preserve provider/profile/native resume hints. Resume succeeds only when the provider capability path confirms it; unsupported resume is explicit. | Provider binding repository and capability-aware adapter tests. | Codex/Claude/ACP production resume matrix remains a later provider task. |
| Agent timeline and live catch-up | SQLite append-only timeline with per-session sequence | Live event channel in `AgentManager` and remote WebSocket streams | Clients fetch authoritative timeline after the last known sequence, then apply live events. Live stream state is discarded on restart. | Timeline sequence/catch-up tests and remote Agent fetch paths. | Add release smoke that reconnects a remote client after manager recreation. |
| Permission requests | SQLite permission rows and timeline permission events | Provider callback waiters and client approval UI | Pending permission records remain durable. Provider callback handles are runtime-only; after restart the session must resume or move to a non-running state before callback mutation. | Permission repository/session tests. | Need explicit stale provider-callback recovery once real resume exists. |
| Scheduled tasks and runs | SQLite `scheduled_tasks` and `scheduled_task_runs` | `ScheduledTaskRunner`, timers, provider execution handles | Scheduler startup calls stale-run recovery; old `running` runs become failed with bounded redacted diagnostics. | `ScheduledTaskRunner::recover_stale_runs` tests. | Real provider scheduled smokes stay explicit and outside default checks. |
| Terminal metadata and live PTY runtime | SQLite terminal metadata rows | `TerminalManager`, PTY child process handles, output ring buffers | Terminal list merges stored metadata with live PTY sessions. Stored `running` terminals missing from live runtime become `stale` with `closed_at_ms`. | `cargo test -p vibex-remote terminal_list_marks_missing_live_terminal_stale`. | Release UI should surface stale terminal state without replaying lost terminal output. |
| Git snapshots and worktree operations | SQLite Git snapshot rows plus Git repositories/worktrees on disk | Git service command execution and filesystem locks | Snapshots reload as last known evidence; current status must be re-read from Git before mutation. Worktree side effects need durable intent/recovery records before broad release. | Git smoke/status and snapshot persistence paths. | Add interrupted worktree-operation recovery once managed-worktree workflows mature. |
| Provider profiles, MCP, skills, prompts, hooks | SQLite/provider config tables and Vibex-scoped config files | Provider config service cache and adapter runtime injection | Reload typed config from SQLite/files. Runtime injection plans are regenerated and redacted; native home config is not rewritten unless explicitly exported. | Provider config, injection preview, redaction, and backup/rollback tests. | Release smoke should prove config reload after app restart. |
| Remote devices, pairing, and audit | SQLite remote device, pairing-code, and audit rows with hashed/redacted material | Remote WebSocket sessions and in-memory auth contexts | Trusted/revoked devices and audit rows reload from SQLite. Pairing codes remain hash-only and expiry/claim state is authoritative. Live connections must reauthenticate. | Remote pairing/auth/audit repository and protocol tests. | Add reconnect smoke after service restart with a trusted test device. |
| Relay local/server connection state | No durable room state in Relay server; optional local client settings in SQLite/config | Relay server rooms, bridge channels, heartbeats, local outbound connection | Relay rooms and bridge response channels are ephemeral. Heartbeats expire stale rooms. Business payload remains encrypted/opaque to Relay. | Relay heartbeat expiry and E2EE frame tests. | Public Relay persistence is out of scope; document reconnect UX when PC is offline. |
| Diagnostic bundles | Filesystem bundle directory and manifest created on demand | Diagnostic export command runtime | Bundles are evidence artifacts only, not recovery inputs. Export reads authoritative sources and redacts sensitive categories. | `pnpm smoke:diagnostics`. | Keep bundle schema aligned with new recovery evidence categories. |
| Backup and restore | Filesystem backup directory with manifest and SQLite database artifact | Backup/restore command runtime | Restore inspects manifest before writing to an explicit disposable/nonexistent target. Restored DB then runs normal migrations and repository reads. | `pnpm smoke:backup`. | Add user-facing restore flow and default database replacement policy later. |

Recovery evidence must stay bounded and redacted. It must not include prompt
bodies, Agent messages, terminal output, file contents, environment values,
provider-native payloads, native ids, raw Git diffs, raw logs, secrets, auth
tokens, pairing codes, or plaintext key material.
